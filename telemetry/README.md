# 12:00 테스트 플레이 기록

이름이 화면과 시트의 플레이어 ID입니다. 이름 + 4자리 숫자의 SHA-256 식별값(profile_id)으로 동명이인을 구분하고, 매 새 게임마다 다른 run_id로 회차를 나눕니다. 4자리 번호 원문은 저장하거나 전송하지 않습니다. 번호는 계정 인증·클라우드 저장 복구 용도가 아닙니다. 게임 진행 저장은 기존처럼 해당 브라우저에 남습니다.

## 현재 연결 상태

`v2/telemetry-config.js`의 endpoint는 비어 있습니다. 실제 Google Sheet 전송은 아직 활성화되지 않았습니다. 설정 전에도 플레이어가 시작 화면의 수집 안내를 보고 시작한 회차는 최근 기록을 해당 브라우저에 임시 보관합니다. 메뉴에서 기록 공유를 끄면 전송 대기 기록도 지웁니다. QA 모드의 가상 플레이는 수집하지 않습니다.

## 수신 시트 설정

1. 소유자의 **비공개** 구글시트에서 확장 프로그램 → Apps Script를 엽니다.
2. `Code.gs` 내용을 붙여 넣고 `setup`을 한 번 실행합니다. 이때 구글의 권한 확인은 소유자가 진행합니다. events / players / runs / dashboard 탭이 생성됩니다.
3. 배포 → 새 배포 → 웹 앱을 선택합니다. 실행 계정은 소유자, 접근 범위는 게임 방문자의 요청을 받을 수 있는 범위로 설정합니다. 시트 자체를 공개 편집으로 전환하지 않습니다. 이 엔드포인트는 기록 추가 용도이며 시트 조회 API는 제공하지 않습니다.
4. 배포된 `/exec` URL을 `v2/telemetry-config.js`의 endpoint에 넣고 게임을 다시 배포합니다. `/dev` URL은 사용하지 않습니다.
5. 실제 브라우저에서 테스트 이름과 4자리 번호로 시작해 `events`에 `run_start`가 들어오는지 확인합니다. 일반적인 CORS 전송이 허용되는지도 이 단계에서 확인해야 합니다. 확인 응답을 읽지 못하면 클라이언트는 성공으로 표시하거나 기록을 삭제하지 않고 재시도합니다.
6. 선택 사항: Apps Script 프로젝트 설정 → 스크립트 속성에 `TESTER_NAMES`를 쉼표로 구분해 지인 이름 목록을 지정합니다. 목록을 설정하면 그 이름만 받습니다. 이름 목록은 강한 인증 수단이 아니며, 이 구성은 소규모 테스트용입니다.

## 기록 내용

이름·식별값·회차, 버전, 게임 날짜/시간/장소, 목표·스토리 단계, 행동과 조건 미충족 사유, 게임 내 컨디션·보유 물/식량·장비, 실수·패닉·회복·사망, 활성 플레이 시간, 모바일/PC와 화면 크기를 제한된 필드로 기록합니다. 연락처·이메일·4자리 번호·자유 입력·전체 저장 파일은 받지 않습니다. 사망 원인은 확인 가능한 상태로 분류하고, 애매하면 `other_or_multiple`로 남깁니다.

## 전송 및 운영

- 30초 주기로 최대 20건씩 전송하며, 응답에서 확인된 event_id만 대기열에서 삭제합니다.
- 오프라인/연결 오류 시 게임은 계속 진행되고 이후 재시도합니다. 이때 원문 번호를 다시 요구하지 않습니다.
- 재시도 중복은 시트 event_id로 제거합니다. 요약은 원본 events에서 다시 계산하므로 재전송으로 회차나 패닉이 중복 집계되지 않습니다.
- 페이지를 닫는 순간의 마지막 요청은 보장할 수 없습니다. 전송 전 기록은 다음 방문 때 재시도합니다. 브라우저 데이터를 지우면 아직 전송하지 않은 기록도 사라집니다.
- 대기열은 최신 400건을 보관하며, 한도 초과 시 일반 행동/하트비트부터 줄입니다.
- 시트의 players는 이름+번호 조합별, runs는 새 게임별, dashboard는 전체 집계입니다.
- 수신기는 입력 길이·필드·숫자를 검사하고, 이름 등 문자열의 수식 실행을 막습니다. 시트 ID는 서버의 Script Properties에만 둡니다.
- 소규모 테스트를 전제로 요약을 원본 로그에서 재구성합니다. 로그가 커지면 Apps Script 실행량과 시트 처리 시간을 확인하고 별도 수집 서버/DB로 이전합니다.
